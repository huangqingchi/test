# 按通用规范进行的项目审查

日期：2026-10-25。审查依据是根目录 [all_project_readme.md](../all_project_readme.md)。先创建本地计划，再检查代码、复现与修正、逻辑/模拟/CPU 测试，最后补齐本目录的结构和流程文档。计划不属于交付物。

## 已发现并修正

| 优先级 | 触发条件与原行为 | 影响 | 修正及证据 |
| --- | --- | --- | --- |
| 高 | 快速验收目标已有旧样片，生成子进程退出 0 但没有产生新文件；父进程验证目标路径 | 可能把旧文件当成本次成功 | 改为独立临时生成目录，必须产生本次文件且父进程验证通过后才替换目标；新增旧产物/验证失败/报告路径冲突测试 |
| 高 | 验收父进程收到 SIGTERM，原先没有处理；普通超时只保证直接子进程终止 | 报告可能留在 running，子进程或后代可能继续占用资源 | 新增 process_runner：Linux 独立进程组、取消处理与回收；shell 向验收进程转发并等待；新增真实 SIGTERM 和后代超时测试 |
| 中 | 空提示词或非 MP4 输出直到模型下载后的生成入口才校验 | 浪费依赖安装和大模型下载时间 | preflight 在 GPU 探测/依赖安装/模型下载前验证；解释器缺失时仍需先准备解释器。新增“错误时不触发 GPU 探测”测试 |
| 中 | manifest 不是合法 JSON、顶层是数组、缺少 files 或 files 类型错误 | AttributeError/KeyError 等内部异常，没有清晰恢复指令 | 校验顶层/文件映射/文件大小类型，统一提示 `bash deploy.sh --download` 重建；已用真实临时损坏清单复现并回归 |
| 文档 | 缺少当前模块结构、进程/模式分支和错误处理图 | 维护与交付信息分散 | 新增 [代码结构](code_structure.md)、[代码流程](code_flow.md)，同步 README/HANDOFF |

旧产物误判通过受控替身复现：子进程模拟退出 0、不写新文件，验证器按“已有文件有效”处理，旧版返回 passed。新回归要求在调用验证器之前发现没有新文件，返回失败，保留旧文件。此模拟不伪装成真实模型生成。

## 按规范逐项评估

| 项目 | 当前结果 | 保留限制 |
| --- | --- | --- |
| 解释器与环境 | 自动选择稳定 Python，按现有 apt 源安装匹配 venv，项目隔离安装 | 不添加 PPA，不适配所有发行版；驱动与权限仍需提前具备 |
| 依赖 | 固定直接版本、CUDA 配对、Diffusers 提交；pip check 与实际导入 | 间接依赖不是完整 hash lock；没有全套离线安装包 |
| 模型范围 | 同一固定 H3 revision，包含两套生成权重和所有共享组件 | 本地权重以公开版本为界；托管 API 模块不属于本地能力 |
| 路径/缓存 | 默认路径及已有环境变量清楚，缓存支持补下载，清单升级检查完整集合 | 没有统一配置文件加载；大小检查不能发现同大小内容损坏 |
| 日志/报告 | 每次独立前缀、阶段耗时、依赖清单、逐工作流 JSON、失败恢复说明 | 未实现日志轮转/自动脱敏，最早期失败只有终端输出 |
| 进程/线程 | 一个 GPU 任务，按工作流独立进程串行；Linux 生成组超时/取消回收 | 没有跨目录 GPU 调度、业务线程池或统一线程配置；强杀/断电不能保证报告完整 |
| 输入/产物 | 组合与媒体限制验证，原子编码和新文件复核 | 参考素材解码仍可能增加内存；结构验收不判断业务画质 |
| 文档/流程 | 通用规范和项目 README 分离；新增结构/流程图与审查记录 | 后续每轮修改必须同步，不能依赖本次文档永久不变 |

## 本轮验证事实

- Windows 标准 Python：发现 60 项，实际通过 38 项；16 项 Linux 专属测试与 6 项需要 CPU 依赖的测试在该环境跳过。
- 独立 CPU 依赖环境：6 项真实索引/媒体接口测试通过；另有运行库导入和 H.264/AAC 实际编码/解码通过。
- Bash 语法、ShellCheck、diff 检查通过。
- Linux 真实取消/后代进程测试和完整 Bash 编排：等待本次 Ubuntu CI 执行后更新记录；不能由 Windows skip 推断通过。
- 首轮 Ubuntu CI 捕获到测试自身的 `/proc` 读取竞态：进程已经被回收时除了 FileNotFoundError，也可能返回 ProcessLookupError。测试已把两者均视为进程消失，仍会对存活进程失败；正在复跑验证。
- 目标 GPU 完整模型下载、权重加载、三流程推理、资源峰值及画质：**尚未执行**。

当前 CI 分成静态/回归和 CPU 集成两个 job，理论合计执行 60 个独立用例，但以实际运行记录为准。无需为了文档更新再次下载约 196GiB 的模型或声称已经部署到目标服务器。

## 交付与后续优先级

本轮修复不改变三个工作流、模型版本或 GPU 配置。正式服务器验收前，优先确认硬件/驱动、网络、磁盘与安装权限，并执行 `bash deploy.sh` 或已有环境上的 `--test-all`。

可重复离线构建、跨目录 GPU 队列、统一线程/资源指标、日志生命周期是后续改进项，不是本次已经实现的功能。现场测试后应保留真实报告、样片和峰值资源，再决定是否扩展并发或调整硬件门槛。
